# Вампирская игра — брифинг для Claude Code

Nov 21, 2026 · @Юрий

Цель: цифровая версия игры на TypeScript, в которую можно играть одному, втроём за одним компьютером и с ботами в любом кресле, плюс симулятор тысяч партий для статистики баланса. Правила — единственный источник истины, код их не додумывает.

## Как запустить

1. Создайте пустую папку проекта, например vampire-game, и внутри неё папку docs.
2. Экспортируйте документ «Сводные правила» в Markdown и сохраните как docs/rules.md. Этот брифинг сохраните как docs/brief.md.
3. В приложении Claude откройте вкладку Code и выберите папку проекта.
4. Первое сообщение: «Прочитай docs/brief.md и docs/rules.md. Выполни этап 0 и остановись для проверки».
5. После каждого этапа проверяйте результат и пишите «следующий этап». Не просите сделать всё сразу.

На Pro все субагенты тратят общий лимит. Держите не больше двух агентов одновременно, для написания кода и ревью достаточно Sonnet.

## Архитектура

Проект из пяти независимых пакетов; зависимости идут только сверху вниз, ядро ничего не знает об интерфейсе и ботах.

| Пакет | Что делает | От чего зависит |
| --- | --- | --- |
| data | Таблицы правил: локации, слоты, персонажи, профессии, здания, участки, треки, пороги, жетоны боя | ни от чего |
| core | Чистый движок правил: состояние, допустимые действия, применение действия, подсчёт очков | data |
| bots | Случайный бот, эвристический бот, ISMCTS | core |
| sim | Консольный симулятор: прогон N партий, сбор статистики в CSV/JSON | core, bots |
| web | Браузерный интерфейс: игра за одним компьютером, бот в любом кресле, просмотр записи партии | core, bots |

Стек: TypeScript, npm workspaces, Vitest для тестов, Vite + React для web.

## Требования к ядру

- API ядра: createGame(config, seed), getLegalActions(state), applyAction(state, action) → новое состояние + события, getObservation(state, player), isTerminal(state), getScores(state).
- Каждый выбор игрока — это действие: драфт, назначение улучшения, сброс за отступные, размещение, решение о вытеснении, направление обмена в Мессе, выбор участка, жетон боя, перемещение Шпиона, оплата содержания, пас. Так человек и бот используют одно и то же API.
- Состояние неизменяемо и сериализуется в JSON; вся случайность — через генератор с seed, чтобы любую партию можно было воспроизвести.
- Скрытая информация (жетоны боя до вскрытия, жетоны профессий локаций) видна игроку только через getObservation.
- Эффекты персонажей и зданий — обработчики, зарегистрированные по id из data. Новая карта или правка цифры не должна требовать правки остального кода.
- Спорные или изменяемые правила выносятся в config как переключатели с текущим значением по умолчанию.
- Инварианты проверяются после каждого действия в режиме разработки: ресурсы не отрицательны, треки в пределах максимума, не больше 3 зданий типа у игрока, одна Цитадель на регион, число рабочих постоянно.

## Роли агентов

Создайте их в .claude/agents/. Основная сессия планирует и раздаёт задачи.

| Агент | Задача | Чего не делает |
| --- | --- | --- |
| implementer | Пишет код одного модуля этапа и тесты к нему | Не меняет правила и не трогает чужие пакеты без задачи |
| reviewer | Проверяет архитектуру, границы пакетов, читаемость, покрытие тестами | Не пишет новую функциональность |
| rules-auditor | Сверяет реализацию с docs/rules.md пункт за пунктом, пишет тесты-сценарии по правилам, ведёт список расхождений | Не додумывает правила: всё неясное записывает в docs/open-questions.md |

Любое неясное правило не угадывается: оно попадает в docs/open-questions.md, а в коде становится переключателем в config.

## Этапы

0. Скелет репозитория, пакеты, CLAUDE.md с правилами работы, файлы агентов. Игровой логики нет.
1. Данные и базовый раунд: локации, размещение, вытеснение, госпиталь, вход в Город, бои без жетонов, конец раунда, ротация первого игрока.
2. Драфт, профессии, улучшения, содержание кровью, отступные, Таверна.
3. Полный бой: жетоны боя и их сброс, Шпион, Отступление, Комиссариат, Склепы.
4. Здания, участки с доплатой, Цитадели, влияние, престиж, финальный подсчёт, тай-брейк.
5. Все 25 персонажей, каждый со своим тестом.
6. Случайный бот и симулятор: 10 000 партий без единой ошибки и нарушения инвариантов.
7. Веб-интерфейс: игра втроём за одним компьютером, выбор бота для любого кресла, лог и перемотка партии.
8. Эвристический бот и ISMCTS; отчёт статистики: винрейт по месту за столом, по стратегиям, по персонажам и профессиям, частота ничьих, распределение ПО.

Этап считается готовым, когда все тесты проходят, reviewer и rules-auditor не нашли блокирующих замечаний, а в docs/progress.md записано, что сделано и что осталось.
