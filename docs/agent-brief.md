# Бриф для агента: проект «Вампирская игра»

Ты подключаешься к проекту без истории переписки. Этот файл — всё, что нужно, чтобы продолжить работу: что
за проект, как он устроен, как в нём принято работать и где что лежит. **Правила игры — в `docs/gdd.md`**
(приложен отдельно); здесь они не повторяются.

## 1. Что это

Цифровая версия авторской настольной игры (автор — владелец репозитория, отвечает на вопросы о правилах):

- **движок правил** (чистый TypeScript, детерминированный);
- **боты** (случайный и эвристический), которые ходят через тот же API, что и человек;
- **симулятор** — прогоняет сотни партий ботов и собирает статистику для баланса;
- **браузерный интерфейс** — игра за одним компьютером, боты в любом кресле, онлайн-партия по ссылке.

Основная текущая работа — **баланс**: автор играет живые партии и смотрит прогоны, присылает правки
(цифры, тексты карт, механики), агент вносит их, проверяет тестами и прогоняет статистику.

Репозиторий: `https://github.com/batmate-code/kingdom`, рабочая ветка `online/p2p`.

## 2. Как общаться с автором

- **Всё по-русски:** сообщения, комментарии в коде, тексты интерфейса, документы, названия тестов.
  Идентификаторы в коде — по-английски (`crypt`, `mercenary`, `forest`).
- Автор пишет коротко и по делу, часто списком правок «по дефолту». Каждую правку вносить как правило по
  умолчанию, если не сказано «экспериментом».
- Если правка неоднозначна (не названа цифра, непонятно, о какой карте речь) — сделать разумно и **явно
  назвать своё допущение** в ответе, а не молчать.
- Перед значимыми изменениями баланса полезно показать расчёт (модели в `docs/balance/`), но решает автор.
- **Коммитить и пушить только по просьбе автора.**

## 3. Запуск

Нужны Node.js ≥ 20 и Git.

```
npm install
npm run dev        # интерфейс: http://localhost:5173 (?cards — все карты персонажей по стоимости)
npm run check      # typecheck + eslint + prettier --check + vitest — должен проходить перед коммитом
npm test           # только тесты
npm run format     # prettier --write
npm run online     # сборка + ретранслятор + туннель Cloudflare: печатает публичную ссылку для друга
```

**Симулятор** (пути отчётов — относительно `packages/sim`, папку создать заранее):

```
npm run sim -- --games 100 --bot heuristic --players 3 --seed 1 \
  --rule disabledCharacters=false --rule influenceModel=reverse \
  --report ../../docs/stats/<дата>/report.md --stats ../../docs/stats/<дата>/stats.json
```

100 партий идут ~11 минут — запускать в фоне. Отчёт: локации, персонажи (взятие, победы держателя,
норма 33 %), ресурсы, влияние, здания на звезде, спуск по трекам, жетоны боя, участки. Разбор прогона
кладётся рядом в `analysis.md` (см. примеры в `docs/stats/2026-11-24*`). 100 партий — шум ±5 п. п.

`npm run agent -- …` — консольная партия для LLM-агента против ботов (описание в `packages/sim/src/agent.ts`).

**Известная ловушка Vite:** после массовых правок dev-сервер отдаёт устаревшие модули (пустая страница или
ошибка «does not provide an export named …»). Лечится `touch` изменённых файлов + Ctrl+F5.

## 4. Архитектура

npm workspaces, пакеты в `packages/`. Зависимости строго сверху вниз (проверяет ESLint
`no-restricted-imports`); импорт между пакетами только через `@vampire/*`. Пакеты экспортируют исходники
TypeScript (`exports: ./src/index.ts`), отдельной сборки библиотек нет.

| Пакет           | Назначение                                                                                      | Зависит от       |
| --------------- | ----------------------------------------------------------------------------------------------- | ---------------- |
| `@vampire/data` | Таблицы правил как чистые данные: локации, персонажи, параметры эффектов, здания, треки, жетоны | —                |
| `@vampire/core` | Чистый движок правил                                                                            | data             |
| `@vampire/bots` | Случайный и эвристический боты                                                                  | core, data       |
| `@vampire/sim`  | Симулятор, отчёты, консольная игра для агента                                                   | core, bots, data |
| `@vampire/web`  | Vite + React + Zustand, CSS-модули; онлайн                                                      | core, bots, data |

### Ядро (`packages/core/src`)

- **API:** `createGame(config, seed)`, `getLegalActions(state)`, `applyAction(state, action)` →
  `{ state, events }`, `getObservation(state, player)`, `isTerminal(state)`, `getScores(state)`,
  `determinize(observation, rng)` (для ботов и экрана гостя).
- **Конечный автомат:** в состоянии всегда есть `pending` — кто и что сейчас выбирает. Каждый выбор игрока —
  действие (`Action`), и человек, и бот ходят только через `getLegalActions`/`applyAction`.
- **Очередь задач:** незавершённая цепочка эффектов хранится в `state.tasks` как сериализуемые записи
  (`{ t: 'askLocationAction', … }`), без замыканий. Движок снимает задачи, пока не упрётся в решение.
- **Состояние** неизменяемо (Immer), сериализуется в JSON без потерь. Запись партии = `config + seed + actions`.
- **Случайность** только через seed-генератор в состоянии (`rng.ts`); `Math.random`/`Date.now` в
  data/core/bots запрещены линтером.
- **Скрытая информация** (жетоны боя до вскрытия, порядок колоды, генератор) — только через `getObservation`;
  события фильтруются `eventsFor`.
- **Инварианты** (`invariants.ts`) проверяются после каждого действия в режиме разработки: ресурсы ≥ 0,
  треки в пределах, ≤ 3 зданий типа, места на звезде, число рабочих, состав колоды.

Ключевые модули:

| Файл                                      | Что внутри                                                                  |
| ----------------------------------------- | --------------------------------------------------------------------------- |
| `engine.ts`                               | `createGame`, `applyAction`, реестр задач `TASKS`                           |
| `decisions.ts`                            | обработчики решений по виду `pending`                                       |
| `round.ts`, `draft.ts`, `upkeep.ts`       | раунд, драфт/улучшение, содержание                                          |
| `placement.ts`                            | размещение, вытеснение, порядок эффектов                                    |
| `locationActions.ts`                      | действия слотов локаций — реестр `HANDLERS` по `kind` из data               |
| `characters.ts`                           | эффекты персонажей — реестр `EFFECTS` по id                                 |
| `professions.ts`                          | профессии                                                                   |
| `combat.ts`                               | сила, жетоны боя, исход, награда                                            |
| `buildings.ts`                            | стройка, участки, Шпиль/Обелиск                                             |
| `reverse.ts`                              | обратные треки (спуск, отметки, места на звезде)                            |
| `economy.ts`                              | ресурсы, влияние, вход в Город, оплата с Алхимиком                          |
| `config.ts`                               | `RuleToggles`, `DEFAULT_RULES`, `RULE_OPTIONS` (чекбоксы при старте партии) |
| `labels.ts`, `visibility.ts`, `scores.ts` | подписи ходов, видимость событий, подсчёт ПО                                |
| `testing.ts`                              | помощники тестов (`newGame`, `place`, `act`, `edit`, `setResources`…)       |

### Данные (`packages/data/src`)

- `board.ts` — локации и слоты (`SlotAction` с дискриминантом `kind`), участки, треки, бонусы треков.
- `characters.ts` — карты (имя, содержание, текст), `UPKEEP_TIERS`; `effects.ts` — `CHARACTER_PARAMS`.
- `buildings.ts`, `combatTokens.ts`, `professions.ts`, `game.ts`, `reverseInfluence.ts`.

### Боты (`packages/bots/src`)

- `random.ts` — случайный легальный ход.
- `heuristic/` — для каждого хода: `determinize` → применить → доиграть свою цепочку → `evaluate` (свои ПО
  минус сильнейший и средний соперник). Оценка «на будущее» — по таблицам:
  `weights.ts` (цены ресурсов в золоте, золото → ПО, влияние, здания, бой) и `characterValues.ts` (ПО за одно
  срабатывание каждого персонажа). **После правок карт/локаций таблицы бота надо сверять вручную** — иначе
  статистика прогонов искажается.

### Интерфейс (`packages/web/src`)

- `App.tsx` — экран партии; `store.ts` — Zustand (партия, история для отмены, сохранение в localStorage).
- Поле — SVG: `board/BoardSvg.tsx`, геометрия в `board/geometry.ts`, анимация фишек `board/tokenMotion.ts`.
- Окна: драфт, выбор действия по шагам (`ChoiceModal` + `choiceSteps.ts`), жетон боя, итоги боя, раунд,
  конец партии. Подсказки слотов — `slotLines.ts`. Карты — `CharacterCard.tsx`, арт в `assets/art/*.webp`.
- Шрифты в сборке: Forum (заголовки) и Cormorant SC (текст), пакеты `@fontsource/*`.
- **Онлайн** (`online/`): хост держит партию в своём браузере; гости получают полный снимок наблюдения с номером
  версии и шлют только ходы; ключ кресла в ссылке-приглашении. Транспорт — ретранслятор WebSocket
  (`relayHub.ts`, поднимается `scripts/online.mjs`) через туннель Cloudflare. План и ревью — `docs/online-plan.md`.

## 5. Правила работы с кодом

- **Источник истины по правилам:** `docs/gdd.md` (актуальная сводка) → история решений в
  `docs/author-answers-*.md` (свежие перекрывают старые) → `docs/rules.md` (исходные правила, во многом
  устарели). Код правила не додумывает.
- **Неясное правило не угадывается:** вопрос в `docs/open-questions.md` (номер, ссылка, варианты), в коде —
  переключатель в `RuleToggles` со значением по умолчанию и комментарием `// OQ-<номер>`.
- **Решение автора** записывается пунктом в `docs/author-answers-2026-11-23.md` (сейчас последний — п. 63).
- **Все числа правил** — именованные константы в `@vampire/data`; литерал числа правила в core недопустим.
  Тесты тоже берут числа оттуда (`CHARACTER_PARAMS as P`), где это разумно.
- Новая механика, персонаж, здание — **со своим тестом**. Тест лежит рядом: `foo.ts` → `foo.test.ts`;
  сценарии по правилам — `*.rules.test.ts`, в названии — ссылка на правило/решение автора.
- TypeScript strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`; без `any` и лишних `as`;
  union-типы с дискриминантом `type`/`kind`.
- `npm run check` должен проходить. Prettier форматирует и `.md`.
- Старые тесты, проверяющие прежние правила, обычно фиксируют их через `newGame` из `testing.ts` (там
  закреплены прежние переключатели) или явный `rules: { … }`; новые правила — отдельными тестами.
- В `.claude/agents/` есть роли implementer, reviewer, rules-auditor (для крупных этапов).

### Типичная правка баланса — чек-лист

1. Цифра/эффект → `packages/data` (параметр в `effects.ts`, текст карты в `characters.ts`, слот в `board.ts`).
2. Новая логика → обработчик в `core` (эффект персонажа, действие слота) + подписи (`labels.ts`,
   `web/src/slotLines.ts`, `choiceSteps.ts`, если меняется вид выбора).
3. Тесты: обновить старые под новое число, добавить тест на новое поведение.
4. Таблицы бота (`weights.ts`, `characterValues.ts`) — если изменилась ценность.
5. Пункт в `docs/author-answers-2026-11-23.md`; при необходимости — `docs/gdd.md`.
6. `npm run check`; по просьбе — прогон симулятора и разбор.

  только рост влияния). Обсуждается — учить ли бота спуску.

  правок (п. 63) свежего прогона ещё не было.
- Модель цен автора: влияние ≈ 7,5 золота, руда 3, компромат 1, жетон силы 2, право стройки 4–5; бот
  настроен близко к ней.
