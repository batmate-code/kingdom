## 1. Что хорошо (и почему менять правила дёшево)

- **Ядро — чистые функции над сериализуемым состоянием**: `getLegalActions / applyAction / getObservation`. Интерфейс, боты, симулятор и онлайн ходят через один API.
- **Реестры с исчерпывающими типами**: персонажи (`characters.ts: EFFECTS: Record<CharacterId, …>`), решения (`decisions.ts: { [K in Decision['kind']]: … }`), действия локаций (`HANDLERS`), видимость событий (`visibility.ts`), картинки и тексты зданий в интерфейсе. Добавил новый id — TypeScript покажет каждое место, которое надо дописать.
- **Переключатели правил** (`RuleToggles`, 21 штука) + значения по умолчанию в одном месте; симулятор принимает любые через `--rule`.
- **Строка решения генерик**: новый вид решения сам появится внизу экрана (подпись — `actionLabel` из ядра). Поле знает только «размещение» и «стройку».
- **Онлайн изолирован полностью**: протокол шлёт `Observation` + список допустимых ходов + события; проверка хода гостя — сравнение со списком из ядра. Любая механика работает онлайн без единой правки в `online/`.
- **Боты** оценивают позицию через движок (просмотр ходов), поэтому новые правила не ломают их — только делают эвристику менее точной.

## 3. Хардкод: что нашёл

### Баги уже сейчас (число в тексте отстало от правил)

1. `web/src/Board.tsx:330` — «Цитадель доступна… **7 золота + 3 руды**», а по правилам 6 + 2 (`citadelCost=cheap`). Компонент старый и уже не рендерится, но лежит в коде.
2. `web/src/Board.tsx:80` — «**2** силы за рабочего в госпитале» вместо `COMMISSARIAT_STRENGTH_PER_WORKER`.
3. `core/src/labels.ts:82` — «× **4** крови → руда» вместо `bloodPerOre`; `:115` — «+**2** влияния» вместо `CHARACTER_PARAMS.manipulator.influenceGain`; `:149` — «+**1** влияние» вместо `COMBAT_REWARD.bonusInfluence`.

### Дублирование (сломается при следующей правке цифры)

4. Тексты карт в data повторяют числа из параметров: 22 персонажа, 3 профессии, 4 жетона боя. Пример: `manipulator.text: '… +2 в другом'` и `CHARACTER_PARAMS.manipulator.influenceGain: 2`. Здания уже сделаны правильно — текст собирается из `BUILDING_EFFECTS`.
5. Чекбоксы экспериментов (`App.tsx: EXPERIMENTS`) — ручной список с текстами вроде «+2 крови на старте».
6. `config.ts:152` — `playerCount ?? 3` (число игроков по умолчанию — не константа data).

### Можно заменить переменными: оценка

| Что                        | Сколько               | Как                                                                                                   |
| -------------------------- | --------------------- | ----------------------------------------------------------------------------------------------------- |
| Тексты карт с числами      | ~29 текстов           | шаблоны: `text: (p) => \`Положи ${p.ore} руды…\``или функция`cardText(id)` в data рядом с параметрами |
| Подписи ядра с числами     | 3                     | брать из параметров                                                                                   |
| Подписи интерфейса         | 2 (+1 в мёртвом коде) | брать из data                                                                                         |
| Чекбоксы правил            | 4 вручную             | метаданные `RULE_META` (подпись, варианты) рядом с `RuleToggles` → экран строится сам                 |
| Решения со скрытым         | 1 список              | `decisionHidesInfo(kind)` в ядре (рядом с `visibility.ts`)                                            |
| Число игроков по умолчанию | 1                     | `GAME.defaultPlayers`                                                                                 |

Итого **~40 мест**; после этого изменение любого числа правил — правка ровно одной константы.

**Не трогать** (это не хардкод правил): координаты поля, цвета игроков и профессий, веса бота (это параметры модели, они уже вынесены в `weights.ts`), номера слотов 1/2 и кругов драфта (структура, разрешено CLAUDE.md).

## 4. Архитектурные долги (по важности)

1. **Store интерфейса — «божественный объект»** (`web/src/store.ts`, 526 строк): локальная партия, история и отмена, сохранение, онлайн-хост, онлайн-гость, голосование за отмену. Каждая новая онлайн-фича растит его. Разделить на срезы: `game` (партия + история), `online` (комната, гость, голосование), `persistence` (сохранение). Сложность: средняя, 0,5–1 день, поведение не меняется.
2. **Мёртвый код ~1 100 строк**: старое поле `Board` (кроме `PLAYER_COLORS`, `Token`, `slotLines`), `MapBoard.tsx` + `mapGeometry.ts` (макет `?mock=map`). Перенести используемое в маленькие модули, остальное удалить. Сложность: низкая.
3. **Логика жетонов боя зашита по id** (`combat.ts: tokenEffects` — `domination`, `massacre`, `defense` в коде). Новые жетоны и правки Защиты/Доминации — всегда код. Можно описать жетон данными: `{ strength, counterBonus, cancels: ['massacre'], onWin: { influence } , retreat }`. Сложность: средняя; окупится, если жетоны ещё будут меняться.
4. **Сохранение без версии.** В localStorage лежит состояние партии; если правило меняет форму состояния, старое сохранение тихо сломается. Добавить `SAVE_VERSION` и сброс несовместимых сохранений (запись партии `config + seed + actions` уже есть — можно и переигрывать). Сложность: низкая.
5. **Версия онлайна статична** (`PROTOCOL_VERSION = 1`). Через `npm run online` хост и гость получают одну сборку, но при постоянной публикации (Pages) кэш браузера даст разные версии. В `hello` слать хеш сборки (`import.meta.env` при сборке). Сложность: низкая.
6. **Переключатели накапливаются** (21): часть — уже решённые вопросы (`massBloodToGold`, `executionerTargetsSecondSlot`, `commissariatWithoutWorkers` стали правилами). Раз в этап закрывать: решённое — в правило, переключатель удалить вместе с ветками кода. Меньше веток — меньше комбинаций для тестов.
7. **`HIDDEN` в ActionBar** (см. сценарии) — единственное место, где новая механика может тихо открыть скрытую информацию в предпросмотре. Перенести решение в ядро.
8. **Приведения типов** (`as`): core 16, web 13, bots 5 — немного, в основном сборка `Record` из массива; `any` нет нигде. Норма.
